## 1. 产品定位

**一句话**：让老人每天的药"该吃的时候一定知道，吃没吃过一定查得到"。

| 项目 | 说明 |
|---|---|
| 目标用户 | 65 岁以上、每天服用 3 种以上药物的慢病患者，以及协助他们的家属 |
| 核心价值 | 准时提醒 · 一眼看懂 · 能打印给医生 |
| 差异化 | 不做账号、不联网、不做广告、不收数据；唯一卖点是"真的会响，而且看得懂" |
| 明确不做 | 不提供医疗建议、不做剂量判断、不推荐补服、不做诊断 |

### 1.1 三条不可突破的红线

1. **不替用户做医疗判断**。只展示事实数字，结论交给用户和医生。
2. **库存不足不能阻止用户确认服药**。库存只是提示，绝不作为拦截条件。
3. **不承诺一定提醒成功**。所有涉及提醒的文案都要给用户留有"以自身感受和医嘱为准"的余地。

## 2. 核心概念

整个系统分四层，自上而下逐层实例化：

| 层 | 概念 | 含义 | 生命周期 |
|---|---|---|---|
| 1 | 药品 Medicine | 是什么药、什么规格、什么剂型、药盒长什么样 | 长期 |
| 2 | 计划 Schedule | 锚点 + 节奏 + 剂量，即"怎么吃" | 可改、可停 |
| 3 | 服药时刻 Slot | 某天某时应该吃哪些药 | **实时计算，不落库** |
| 4 | 记录 DoseLog | 实际发生了什么 | 只增不改（撤销写反向记录） |

### 2.1 锚点 Anchor —— 几点吃

| 类型 | 示例 | 说明 |
|---|---|---|
| `Clock(hour, minute)` | 08:00 | 固定钟点 |
| `Meal(type, offsetMin)` | 早饭 −30 分钟 | 相对饭点，可随当天饭点变化 |

`MealType` 取值：`BREAKFAST` / `LUNCH` / `DINNER` / `BEDTIME`（睡前即 `Meal(BEDTIME, 0)`）。

### 2.2 节奏 Recurrence —— 哪些天吃

| 字段 | 含义 |
|---|---|
| `startDate` | **基准日，必填**。隔天药的唯一依据 |
| `endDate` | 疗程结束日，null 表示长期 |
| `everyNDays` | 1 = 每天，2 = 隔天，3 = 每 3 天 |
| `weekdays` | 每周固定几天，如 `{MON, WED, FRI}` |
| `monthlyDay` | 每月固定几号 |

四者是**互斥**的，取值优先级：`weekdays` > `monthlyDay` > `everyNDays`。

### 2.3 提醒窗口 ReminderWindow —— 什么算漏

围绕计划时刻定义一段有效区间：

```
窗口 = [计划时刻 − 提前量, 计划时刻 + 延迟量]
```

- 默认提前 30 分钟、延迟 60 分钟，每种药可单独修改。
- 命名规范：对外一律称"**提醒有效时段**"，禁止使用"补服窗口""安全时间"等带医疗含义的词。

### 2.4 剂量 DoseQuantity

以**最小单位 ×10 的整数**存储，禁用浮点。

| 场景 | 存储值 | 显示 |
|---|---|---|
| 1 片 | 10 | 1 片 |
| 半片 | 5 | 0.5 片 |
| 10 ml | 100 | 10 ml |

单位随药品而定：片 / 粒 / 袋 / ml / 滴 / 喷 / U。

## 3. 数据模型

```kotlin
// ---------- 药品 ----------
@Entity
data class Medicine(
    @PrimaryKey val id: Long = 0,
    val name: String,                 // 盐酸二甲双胍片
    val form: MedicineForm,           // TABLET / CAPSULE / LIQUID / DROPS / SPRAY / PEN
    val specValue: Double,            // 每片含量 500
    val specUnit: String,             // mg
    val doseUnit: String,             // 片 / 粒 / ml / 滴 / U
    val splittable: Boolean,          // 能否掰开（缓释片、肠溶片 = false）
    val packSize: Int,                // 30
    val packUnit: String,             // 片
    val imagePath: String?,           // 药盒照片（App 私有目录）
    val expireDate: LocalDate?,       // 有效期
    val openedAt: LocalDate?,         // 开封日（滴眼液等需要）
    val shelfDaysAfterOpen: Int?,     // 开封后可用天数
    val autoDeductStock: Boolean = true,
    val note: String?
)

// ---------- 用药计划 ----------
@Entity
data class Schedule(
    @PrimaryKey val id: Long = 0,
    val medicineId: Long,
    val anchorType: AnchorType,       // CLOCK / MEAL
    val clockHour: Int?,              // anchorType == CLOCK 时有效
    val clockMinute: Int?,
    val mealType: MealType?,          // anchorType == MEAL 时有效
    val offsetMin: Int = 0,           // 饭前为负、饭后为正
    val doseQtyX10: Int,              // 单次剂量，0.1 单位整数
    val startDate: LocalDate,         // 基准日，必填
    val endDate: LocalDate? = null,
    val everyNDays: Int = 1,
    val weekdaysMask: Int? = null,    // 位掩码，周一=1 … 周日=64
    val monthlyDay: Int? = null,
    val earlyMinutes: Int = 30,       // 提前量
    val lateMinutes: Int = 60,         // 延迟量
    val enabled: Boolean = true
)

// ---------- 服药记录 ----------
@Entity
data class DoseLog(
    @PrimaryKey val id: Long = 0,
    val scheduleId: Long,
    val medicineId: Long,
    val plannedAt: Instant,           // 计划时刻，统计基准
    val actedAt: Instant?,            // 实际确认时刻
    val status: DoseStatus,
    val delayMinutes: Int?,           // actedAt − plannedAt
    val certain: Boolean = true,      // 补记 / 记不清 = false
    val reason: String?               // 跳过的原因
)

enum class DoseStatus { PENDING, DUE, TAKEN, LATE, SKIPPED, MISSED, UNCERTAIN }

// ---------- 库存流水 ----------
@Entity
data class StockChange(
    @PrimaryKey val id: Long = 0,
    val medicineId: Long,
    val deltaQtyX10: Int,             // 正数入库、负数出库
    val reason: StockReason,          // PURCHASE / TAKEN / ADJUST / LOST / EXPIRED / UNDO
    val refId: Long?,                 // 关联 DoseLog.id，用于幂等
    val at: Instant,
    val note: String?
)

// ---------- 用户设置（单行表） ----------
@Entity
data class AppSettings(
    @PrimaryKey val id: Int = 1,
    val breakfast: LocalTime = LocalTime.of(7, 30),
    val lunch: LocalTime = LocalTime.of(12, 0),
    val dinner: LocalTime = LocalTime.of(18, 30),
    val bedtime: LocalTime = LocalTime.of(22, 0),
    val mergeWindowMinutes: Int = 10, // 相邻提醒合并阈值
    val quietStart: LocalTime = LocalTime.of(22, 0),
    val quietEnd: LocalTime = LocalTime.of(7, 0)
)
```

**当前库存 = `SUM(deltaQtyX10)`**，不单独存字段，避免双写不一致。

## 4. 关键算法

### 4.1 今天要不要吃

```kotlin
fun Schedule.isDueOn(date: LocalDate): Boolean {
    if (!enabled) return false
    if (date < startDate) return false
    endDate?.let { if (date > it) return false }

    weekdaysMask?.let { mask ->
        val bit = 1 shl (date.dayOfWeek.value - 1)   // MON=0 → bit0
        return (mask and bit) != 0
    }
    monthlyDay?.let { day ->
        val last = date.lengthOfMonth()
        return date.dayOfMonth == minOf(day, last)  // 31 号在 2 月取月末
    }
    return Math.floorMod(date.toEpochDay() - startDate.toEpochDay(), everyNDays.toLong()) == 0L
}
```

**必须用 `toEpochDay()` 差值**，禁止使用 `dayOfYear % 2`（跨年、闰年会错位），也禁止用"今天吃了吗"反推。

### 4.2 锚点 → 具体时刻

```kotlin
fun Schedule.resolveTime(date: LocalDate, s: AppSettings): LocalDateTime {
    val base = when (anchorType) {
        AnchorType.CLOCK -> date.atTime(clockHour!!, clockMinute!!)
        AnchorType.MEAL  -> date.atTime(s.timeOf(mealType!!)).plusMinutes(offsetMin.toLong())
    }
    return base
}
```

结果可能跨日（如 `DINNER 23:50 + 30` → 次日 00:20），下游必须用 `LocalDateTime` 处理，不要假设仍在当天。

### 4.3 时刻聚合

同一天内，若两个 Slot 的计划时刻相差 ≤ `mergeWindowMinutes`（默认 10 分钟），合并为**一次提醒**，弹窗内列出全部药品。避免老人刚吃完又被弹一次。

### 4.4 状态判定

```
有记录：
   actedAt ∈ [planned − early, planned + late]  → TAKEN
   actedAt < planned − early                    → TAKEN（标记提前）
   actedAt > planned + late                     → LATE

无记录：
   now < planned + late                         → DUE
   now ≥ planned + late                         → MISSED
```

用户主动跳过 → `SKIPPED`（**不计入漏服**）；选"记不清" → `UNCERTAIN`。

### 4.5 漏服推导与补偿

- 提醒时同时排一个"判定闹钟"（计划 + 延迟量），到点仍无响应则直接写 `MISSED`，**不依赖 App 进程存活**。
- App 每次回到前台，补算所有"已过窗口且无记录"的时刻。
- 跨天补算时**合并成一条提示**（"昨天有 2 次未确认"），不逐条弹出。
- 静默时段（22:00–07:00）不补发提醒，睡前的药除外。

### 4.6 库存

```kotlin
fun stockX10(medicineId: Long): Int =
    stockChangeDao.sumByMedicine(medicineId)

fun daysLeft(medicine: Medicine, schedules: List<Schedule>, today: LocalDate): Double {
    val need = (0 until 30).sumOf { d ->
        schedules.filter { it.isDueOn(today.plusDays(d.toLong())) }
                 .sumOf { it.doseQtyX10 }
    }.toDouble() / 10.0
    if (need <= 0.0) return Double.POSITIVE_INFINITY   // 不在服药期
    return (stockX10(medicine.id) / 10.0) / (need / 30.0)
}
```

**不能用"每天吃几片"估算**，隔天药会算错一倍，必须按未来 30 天实际规则求和。

扣减规则：

1. 仅在用户确认时扣减，`reason = TAKEN`，`refId = doseLog.id`。
2. 幂等：同一 `refId` 已存在则跳过。
3. 撤销 → 写一条 `UNDO` 正向流水，不删除原记录。
4. 盘点 → 写 `ADJUST` 流水，差值为「实际值 − 当前值」。

### 4.7 记录写入规则

| 规则 | 说明 |
|---|---|
| 幂等 | 一次服药只允许一条 `DoseLog`，重复点击直接忽略（以 `scheduleId + plannedAt` 为唯一键） |
| 撤销窗口 | `TAKEN` 后 **5 分钟内**可撤销；超时后按钮隐藏，只能通过盘点修正库存 |
| 撤销方式 | 记录逆转为待确认状态，库存写一条 `UNDO` 正向流水，原记录保留可追溯 |
| `SKIPPED` | 不扣库存，不计入漏服统计，但计入"应服总次数" |
| `UNCERTAIN` | 不扣库存，`certain=false`，统计中单列 |
| `MISSED` | 不扣库存，由判定闹钟或补算逻辑写入 |
| 未来时间 | 拒绝标记晚于当前时间 30 分钟以上的时刻 |

| 页面 | 内容 | 关键要求 |
|---|---|---|
| 今日服药单（首页） | 今日各时刻任务、已服/待服状态、库存提示、不在服药日的药折叠显示 | 主按钮"已全部服用"≥ 56dp |

| 提醒页 | 药盒图 + 药名 + 剂量清单 + 时间 | 全屏、大字号、TTS 播报 |
| 历史/统计 | 按日列表、按时/延迟/未确认三行汇总 | 不给单一百分比结论 |

规则的自然语言回显示例：

```
维生素 D3      隔天 · 早饭后 1 粒       下次 11-14
阿仑膦酸钠     每周一 · 早饭前 30 分     今天要吃
```

**今天不吃的药必须显式出现一行"今天不用服用"**，不能只靠留白——这是隔天药最常见的认知错误来源。

### 5.1 导出报告规则

| 项目 | 规则 |
|---|---|
| 时间范围 | 近 7 天 / 近 30 天（默认）/ 近 90 天 |
| 版面 | 单页 A4；内容超出时自动分页，不截断表格行 |
| 结构 | 页眉 → 当前用药 → 服药概况 → 按日概览 → 异常提示 → 页脚声明 |
| 文件名 | `用药记录_YYYYMMDD.pdf`，**不得包含病名、药名等敏感信息** |
| 日期格式 | 统一 `YYYY-MM-DD`，避免 `12/11` 这类本地化歧义 |
| 措辞 | 全文只陈述事实，禁止出现"建议""诊断""应当""说明依从性差"等结论性用语 |
| 页脚声明 | "由患者自行记录，未经医疗核实；本应用不提供医疗建议" |
| 语言 | 跟随系统语言（中文 / 英文） |
| 分享 | 通过 `FileProvider` 输出 `content://` URI，分享前提示文件含健康信息 |
| 空数据 | 所选范围无记录时不生成文件，直接提示 |

## 6. Android 实现要点

### 6.1 提醒链路

```
Schedule 变化 / 日期变化
   → 计算下一次触发时刻
   → AlarmManager.setAlarmClock(AlarmClockInfo, PendingIntent)
   → BroadcastReceiver（常驻，独立于进程）
   → 发通知（HIGH 渠道 + 声音 + 震动 + 全屏 Intent）
   → 用户操作 → 写 DoseLog → 扣库存 → 排下一次
```

关键点：

1. 用 `setAlarmClock()` 而非 `setExact()`：属于系统闹钟语义，最不易被延迟，可穿透勿扰。
2. **不需要常驻前台服务**，`PendingIntent` 独立于进程存活，更省电也更好过审。
3. 监听 `BOOT_COMPLETED`、`TIME_SET`、`TIMEZONE_CHANGED` 三个广播，触发全量重排。
4. 每次排程前先 `cancel` 旧的同 `requestCode` 闹钟，避免重复触发。

### 6.2 权限清单

| 用途 | 权限 | 处理方式 |
|---|---|---|
| 准时响 | `SCHEDULE_EXACT_ALARM` | 引导页 + 状态检测，拒绝时降级并明确告知 |
| 发通知 | `POST_NOTIFICATIONS` | Android 13+ 运行时申请 |
| 锁屏强提醒 | `USE_FULL_SCREEN_INTENT` | 作为增强项，不给也必须有声音通知兜底 |
| 重启恢复 | `RECEIVE_BOOT_COMPLETED` | 安装即授予 |
| 拍照 | 系统 `PhotoPicker` | 免申请相机权限，优先使用 |
| 免电池优化 | 跳转系统设置页 | **不直接调用 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`**，改为文字引导 |

### 6.3 数据库与并发

- Room + `Flow` 驱动 UI，不使用预生成的"任务表"。
- 库存写入与 `DoseLog` 写入放在同一事务内。
- 所有时间计算以 `LocalDate` / `LocalDateTime` + 系统 `ZoneId` 为准，禁止用绝对毫秒数做日期加减。

### 6.4 图片处理

- 药盒照片存入 App 私有目录，拍摄后压缩至长边 1080px、JPEG 质量 80。
- 单独生成 240px 缩略图供列表使用，避免列表加载原图。
- 删除药品时同步删除图片文件。

## 7. 多语言（i18n）

### 7.1 语言范围（已确定）

首发 4 种语言：`en` + `zh-CN` + `es` + `pt-BR`。

| 阶段 | 语言 | 主要市场 | 说明 |
|---|---|---|---|
| **P1** | 英语 `en`（默认） | 美、英、加、澳、印度、菲律宾、南非 | 默认兜底，覆盖面最广 |
| **P1** | 简体中文 `zh-CN` | 海外华人（Play 在中国大陆不可用） | 母语审校零成本 |
| **P1** | 西班牙语 `es` | 西班牙 + 拉美 20 国 | **一种语言覆盖 20 多个国家**，性价比最高 |
| **P1** | 巴西葡语 `pt-BR` | 巴西 | Play 下载量常年前三 |
| P2 | 日语 `ja`、意大利语 `it`、德语 `de`、繁体中文 `zh-TW` | 日本、意大利、德奥瑞、台港澳 | 日/意老龄化极高但本地化规范严格；繁体中文转换成本接近零 |
| P3 | 印尼语 `id`、韩语 `ko`、阿拉伯语 `ar`、印地语 `hi`、泰语 `th`、越南语 `vi` | 东南亚、韩国、中东、印度 | 阿拉伯语需整套 RTL 镜像布局，泰语需处理无空格断行 |

选语言的判断标准是**"一种语言能覆盖多少个国家"**，不是单一国家的人口。首发 4 种均为低成本语言（无 RTL、无复杂断行），维护量在可控范围内。

> 第二梯队不要凭感觉加，等 Play Console「探索」报告给出真实下载来源后再定。

### 7.2 资源组织

```
res/
├── values/strings.xml           ← 英文，默认兜底
├── values-zh-rCN/strings.xml    ← 简体中文
├── values-es/strings.xml        ← 西班牙语

```

P2 追加 `values-ja`、`values-it`、`values-de`、`values-zh-rTW`。

- **默认语言放英文**：漏翻时显示英文而不是空白或乱码，这是 Play 的推荐做法。
- 区域写法团队内统一，`values-zh-rCN` 或 `values-b+zh+Hans` 二选一，不要混用。

### 7.3 最大的坑：规则句子禁止拼接

药品规则要回显成一句话（"隔天 · 早饭后 1 粒"），如果按片段拼接：

```kotlin
// ❌ 错误做法
"${intervalText} · ${mealText} ${doseQty}${unit}"
```

中文能拼出正确语序，英文会变成 `Every other day · after breakfast 1 tablet`——量词位置是错的，正确说法是 `1 tablet after breakfast`。

**正确做法：以"规则组合"为单位提供整句模板。**

```xml
<!-- values/strings.xml（英文） -->
<string name="rule_daily_meal">Every day · %1$s</string>
<string name="rule_every_other_day_meal">Every other day · %1$s</string>
<string name="rule_every_n_days_meal">Every %1$d days · %2$s</string>
<string name="rule_weekly_meal">Every %1$s · %2$s</string>
<string name="rule_monthly_meal">Day %1$d of each month · %2$s</string>

<!-- values-zh-rCN/strings.xml（中文） -->
<string name="rule_daily_meal">每天 · %1$s</string>
<string name="rule_every_other_day_meal">隔天 · %1$s</string>
<string name="rule_every_n_days_meal">每 %1$d 天 · %2$s</string>
<string name="rule_weekly_meal">每周%1$s · %2$s</string>
```

子片段（饭点、剂量）同样各自成句，由模板的占位符决定语序：

```xml
<string name="meal_after_breakfast">早饭</string>   <!-- 中文 -->
<string name="meal_after_breakfast">after breakfast</string>   <!-- 英文 -->
```

### 7.4 复数用 `<plurals>`，不要用 if 判断

```xml
<plurals name="dose_tablet">
    <item quantity="one">%s tablet</item>
    <item quantity="other">%s tablets</item>
</plurals>
```

- 英文 1 tablet / 2 tablets，中文"1 片 / 2 片"无变化，但**必须走同一套 plurals 接口**，否则英文必然出现 "1 tablets"。
- 剂量为 0.5 片时，英文走 `other` → `0.5 tablets`，这是正确表达。

### 7.5 日期、时间与数字

| 项目 | 规则 |
|---|---|
| 12/24 小时制 | 跟随系统 `DateFormat.is24HourFormat(context)`，禁止硬编码 |
| 一周起始日 | `WeekFields.of(locale).firstDayOfWeek`（中国周一起、美国周日起） |
| 界面日期 | `DateTimeFormatter.ofLocalizedDate(FormatStyle.MEDIUM).withLocale(locale)` |
| 导出报告日期 | 固定 `YYYY-MM-DD`，跨语言无歧义 |
| 数字格式 | `NumberFormat.getInstance(locale)`，欧洲用逗号作小数点，不能手拼 |
| 时区名称 | 用系统本地化名称，不硬编码 `GMT+8` |

### 7.6 翻译边界

| 内容 | 处理方式 |
|---|---|
| 用户手动输入的药名 | **永不翻译** |
| 药名、批准文号 | 保留原文，不做本地化 |
| 剂量单位 | 按剂型映射：片→tablet、粒→capsule、袋→sachet、滴→drop、喷→spray、U→unit |
| 界面文案 | 全部进 `strings.xml`，包括 Toast、对话框、通知标题 |
| **免责声明与医疗措辞** | **必须人工审校**，机器翻译的医疗声明存在法律风险 |
| 无障碍 `contentDescription` | 同样需要翻译 |

### 7.7 通知渠道的语言陷阱

Android 的通知渠道名称与描述在**首次创建后固化**，切换语言不会自动更新。对策：

1. 渠道名使用不含时间、数量的通用短语（`服药提醒` / `Medication reminders`）。
2. 检测到语言变更时，用**相同 id** 重新调用 `createNotificationChannel` 更新名称——用户对该渠道的开关设置会保留，但 importance 不允许降级。
3. 禁止在渠道名里拼接剂量或日期。

### 7.8 布局必须留余量

- 英文通常比中文长 30%~50%，德语可达 +80%。
- 按钮、标签一律 `wrap_content` + `minWidth`，**禁止固定宽度**。
- 允许换行，不要在按钮上 `maxLines=1` 硬截。
- 用伪语言 `en-XA`（Android Studio 自带）做布局压力测试，它会自动加长 30% 并加注音符号。

### 7.9 语言切换

| 系统版本 | 方式 |
|---|---|
| Android 13+ | 声明 `localeConfig`，接入系统"应用语言"设置，用 `AppCompatDelegate.setApplicationLocales()` 切换 |
| Android 12 及以下 | App 内提供语言选项，切换后重建 Activity |
| 默认行为 | **跟随系统**，不擅自锁定语言 |

### 7.10 商店素材

应用名称、简介、截图同样需要多语言。截图必须是**对应语言的真实界面**，不能用中文截图配英文描述——这是 Play 审核的常见扣分项。

## 9. 分期计划
