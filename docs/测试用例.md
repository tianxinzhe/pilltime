## 0. 使用说明

1. **用例编号**：`模块前缀-序号`，如 `MED-03`。提交缺陷时请引用用例编号。
2. **优先级**：
   - **P0**：阻断发布。不通过则本版本不得提测/发版。
   - **P1**：核心体验。必须修复，特殊情况需产品确认后带缺陷发布。
   - **P2**：一般问题。可排入后续版本。
3. **执行结果**：在「结果」列填写 `通过` / `失败` / `阻塞` / `不适用`；失败必须附缺陷单号。
4. **UI 文案说明**：App 默认语言为英文，用例中的界面文字取自英文资源。中文界面请在 `Settings → Language → 简体中文` 切换后执行对应用例。
5. **默认值基线**（以下用例的预期均基于此，若产品调整需同步更新本文档）：
   | 项目 | 默认值 |
   |---|---|
   | 早饭 / 午饭 / 晚饭 / 睡前 | 07:30 / 12:00 / 18:30 / 22:00 |
   | 提醒提前量 / 延迟量 | 30 分钟 / 60 分钟（08:00 的药 → 窗口 07:30–09:00） |
   | 合并窗口 | 10 分钟 |
   | 静默时段 | 22:00–07:00 |
   | 低库存阈值 | 7 天 |
   | 撤销窗口 | 5 分钟 |
   | 「稍后」间隔 | 10 分钟 |
   | 漏服补算回看 | 7 天 |
   | 允许标记的未来时刻 | 最多 30 分钟 |
6. **测试前置**：每轮执行前卸载重装，确认「引导页 → 首页」链路干净；时间类用例建议使用模拟器（可改系统时间），并关闭自动时间同步。

## 1. 测试范围与发布门槛

| 模块 | 覆盖 | 主要风险 |
|---|---|---|
| 首次启动与权限引导 | 是 | 权限被拒后无法使用 |
| 药品录入（表单/拍照/药名识别） | 是 | 数据丢失、照片未保存 |
| 服药计划（锚点/节奏/剂量/窗口/递减/按需） | 是 | 该吃的不提醒、不该吃的提醒 |
| 今日服药单 | 是 | 状态判定错误 |
| 提醒（通知/全屏/TTS/合并/稍后/跳过） | 是 | 提醒不响、重复响、响错药 |
| 历史与补记 | 是 | 统计口径错误 |
| 库存 | 是 | 扣减/回补错误、剩余天数错误 |
| 报告导出与分享 | 是 | 乱码、泄露隐私、文件损坏 |
| 设置（时间/默认值/暂停/语言） | 是 | 设置不生效 |
| 用药人档案 | 是 | 档案间数据串台 |
| 桌面小组件 | 是 | 数据不刷新 |
| 多语言（14 种） | 是 | 漏翻、截断、语序错误 |
| 系统环境（重启/时区/杀进程/锁屏） | 是 | 提醒丢失或重复 |
| 无障碍与可用性 | 是 | 老年用户无法操作 |

**发布门槛**：全部 P0 通过；P1 遗留缺陷 ≤ 3 且均有产品书面确认；冒烟用例 100% 通过；14 种语言无漏翻。

> 每个厂商机型至少执行：`SMK-06`、`REM-02`、`REM-14`、`SYS-01`、`SYS-02`、`SYS-03`。

### 2.2 构建与安装

```bash
./gradlew assembleDebug          # 产物：app/build/outputs/apk/debug/app-debug.apk
adb install -r app-debug.apk
adb shell am start -n com.alex.pilltime/.MainActivity
```

- 检查安装后桌面图标名称为 **PillTime**，包名为 `com.alex.pilltime`。
- Debug 包已开启伪语言 `en-XA`，用于检查文案截断。

### 2.3 时间类测试技巧

| 场景 | 操作 |
|---|---|
| 快速验证提醒 | 将计划设在 3–5 分钟后，或使用 `Settings → Test reminder in 1 minute` |
| 验证边界（窗口结束） | 把「提前/延迟」调小（如提前 0、延迟 1），再把系统时间拨到边界 |
| 跨天 | 模拟器中关闭「自动设置时间」后修改系统日期 |
| 跨时区 | 系统设置切换时区（如 Asia/Shanghai → Europe/London） |
| 关机补算 | 模拟器冷关机 → 系统时间前进 2 天 → 开机打开 App |
| 通知/闹钟状态 | `adb shell dumpsys alarm \| findstr pilltime`<br>`adb shell dumpsys notification --noredact \| findstr pilltime` |

## 9. 已知限制与非缺陷（测试时勿误报）

1. **静默时段**只抑制「漏服补算」的通知，不抑制已排程的计划提醒（如睡前的药仍会按时响）。
2. **按需（PRN）**药物不参与库存天数预测，不显示剩余可用天数。
3. **全屏提醒**依赖系统权限与厂商 ROM，权限不可用时降级为通知 + 声音，属预期行为。
4. **精确闹钟**未授权时可能延迟或丢失提醒，首页会显示提示条，属预期降级。
5. **补算范围**最多回看 7 天，超过 7 天的漏服不会自动补写。
6. **删除药品/档案**会连带删除其记录，属产品定义行为，不是缺陷。
7. 首页在系统字体最大、超长药名等极端情况下允许换行显示，但不得截断或遮挡操作按钮。
8. 隐私政策链接当前为 `https://example.com/privacy` 占位地址，**发布前必须替换**，测试阶段按 S2 记录跟踪。
9. 「暂停全部提醒」到期后，当前实现需重新打开 App 才会重排闹钟。**此项需产品确认**：若要求到期自动恢复提醒，按 S2 记录缺陷。
10. 库存为单池流水模型，**不记录有效期、开封日期与条码**；药品编辑页与库存页均无相关字段，属产品定义，不是缺陷。
11. 开发期数据库升级使用破坏式重建（`fallbackToDestructiveMigration`），覆盖安装后旧数据会被清空；正式发布前必须改为增量迁移，测试阶段仅在验证升级路径时记录。
